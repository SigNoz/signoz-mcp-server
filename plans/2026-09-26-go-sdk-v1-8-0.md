# Plan: Upgrade the official MCP Go SDK to v1.8.0

Status: In Progress
Issue:
PR:

## Context

The server uses v1.7.0. Upstream v1.8.0 adds bounded stdio input, JSON nesting
checks, and protocol correctness fixes without adding a protocol revision.
The user approved upgrading after reviewing the release and relevant source changes.

## Approach

Upgrade the SDK while retaining current cache metadata, supported protocol
versions, stateless JSON HTTP, tool contracts, and OAuth implementation. Extend
the existing invalid-frame test to cover the new transport limits. Run the
complete local PR gate with CI's Go 1.26 toolchain.

## Files to Modify

- `go.mod`, `go.sum` — SDK dependency and checksums.
- `internal/mcp-server/protocol_matrix_test.go` — malformed, oversized, and
  deeply nested input rejection through the production server and SDK framing.
- `README.md`, `docs/architecture.md` — SDK version and stdio input limits.

## Key Decisions

### 2026-09-26 — Adopt SDK defaults without new product policies

- Keep `SetCacheable` and `SupportedProtocolVersions` unset. Cache policy and
  protocol restrictions require their own operational reason and review.
- Accept the SDK-owned change from unbounded stdio frame buffering to a 16 MiB
  default, and reject JSON nesting beyond 1,000 levels. Oversized requests must
  be split into smaller calls; HTTP retains its existing independent limit.
- Keep catalog fixtures, schemas, metadata, and guardrails unchanged. No
  SigNoz/agent-skills companion change is needed for this runtime upgrade.
- The production HTTP path uses neither SDK OAuth nor stateful sessions, and
  the repository does not configure the removed MCPGODEBUG compatibility flags.

## Verification

- `GOTOOLCHAIN=go1.26.0 go test ./internal/mcp-server -run
  '^TestProductionIOTransport' -count=1 -timeout=90s` — passed both lifecycle
  models and malformed, oversized, and deeply nested frame rejection.
- `GOTOOLCHAIN=go1.26.0 make ci` with an isolated `GOMODCACHE` — passed all
  gates: formatting, lint, dependency verification, build, race tests, 16
  guardrails, real-server Inspector/stdio checks, 6 legacy and 6 modern official
  conformance scenarios, Python style, and repository docs validation.
- The first run found modified shared-cache copies of unrelated
  `github.com/go-openapi/validate` and `github.com/shirou/gopsutil/v4` modules.
  A fresh cache populated from verified module archives passed; shared cache
  contents were left intact. GNU coreutils was installed for the protocol lane.
- Reviewed the diff against section 11 of `docs/mcp-best-practices.md`:
  no tool/schema/result changes, golden re-recording, guardrail relaxations,
  or MUST exceptions. The new transport limits are documented and tested.
- Live SigNoz E2E was not run; the change does not alter upstream backend parsing.

## Outcome

Upgraded to v1.8.0 with no transitive dependency changes. Existing cache and
protocol policies remain in place. The default stdio input limits have regression
coverage and migration guidance. README and architecture documentation match the
runtime; tool metadata and companion agent skills require no change.

Implementation and local verification are complete. The plan remains In Progress
until the PR is opened and linked; mark it Done before that PR leaves draft.
